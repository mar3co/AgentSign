# Sign v1.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Pro extras on the v1 skeleton: branding (name + logo on mail and the signing page), saved packets (PDF + signer roles, send again), and team invites (shared Pro cabinet, cap 10), still $19, no new SKU.

**Architecture:** Same Next.js App Router + Route Handlers + `setDeps` composition root. Cabinet is the Pro owner plus `cabinet_members`. Entitlement is `accounts.plan === "pro"` or `SELF_HOST`. Branding and packets hang off the cabinet owner. Certificate and sealed appearance page stay factual. No new MCP tools.

**Tech Stack:** Existing v1 stack (Next.js, Drizzle, PGlite tests, Vitest, shadcn on Base UI, BlobStore, Resend text+html). No new runtime dependencies unless a task proves one is required.

Sources: [product plan](../../2026-08-19-product-plan.md), [v1.1 design](../specs/2026-08-20-sign-v1.1-design.md).

## Global Constraints

- Its own product. Not a suite SKU. Do not import `ss-core` or AGPL competitor code.
- Working title **Sign**. Apache-2.0.
- Primitive: **no field placer, tags, folders, template CMS, custom domain, seats, SSO, SMS, bulk, second Stripe Price, Enterprise page.**
- **Free path never requires login.** Branding/packets/team are logged-in Pro (or `SELF_HOST`) only. Free cloud callers get `403` `{ "error": string, "code": "pro_required" }`.
- HTTP: Next.js Route Handlers + Zod. Tests call exported `GET`/`POST`/`PUT`/`PATCH`/`DELETE` with `new Request(...)`. Inject `{ db, store, mailer, now, auth }` via `setDeps`. **No Hono.** No tRPC. No Server Actions as the public API.
- UI: shadcn on Base UI. `export const runtime = "nodejs"` on every new route.
- Human always signs. Keys never sign. Ceremony finishes on `/s/:token` without an account.
- Certificate sibling PDF and appended signature page **must not** include display name or logo.
- OTP email is **not** branded.
- MCP remains `send` / `status` / `download` only. Packets/branding/team are REST.
- No `?apiKey=`. Tmp keys cannot call branding/packets/team.
- Errors `{ "error": string, "code": string }`.
- Quiet caps: packets **50** per cabinet (`packet_limit`); team **10** including owner (`team_full`).
- Logo: PNG or JPEG magic, max **256 KiB**. Blob key `branding/{ownerUserId}/logo`. Packet PDF key `packets/{id}/original.pdf`.
- Two clocks unchanged. Team sends use the **cabinet owner's** Pro keep and cap lift.
- Do not create live Vercel or Supabase projects.
- TDD: failing test first, watch it fail, then production code. `fileParallelism: false` already set; `afterEach(resetDeps)`. Call `resetEnvCache()` if a test mutates `SELF_HOST`.
- Fake AuthAdapter: copy the `createFakeAuth` / `magicCookie` pattern from `src/test/keys.test.ts` (cookie `sign_session=`, codes `magic:{email}`).
- Do not commit `.grok/`.

import { getEnv } from "../env.js";
export const TEAM_CAP = 10;
export const PACKET_CAP = 50;
export const LOGO_MAX_BYTES = 256 * 1024;
export function isEntitled(account: { plan: string } | null | undefined): boolean {
  const flag = getEnv().SELF_HOST.trim().toLowerCase();
  if (flag === "1" || flag === "true") return true;
  return account?.plan === "pro";
}
