# Sign v1 Walking Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a dogfoodable signing primitive: someone uploads a PDF with no account, a human signs on a phone, both inboxes get a sealed PDF + certificate, and we hard-delete the bytes in 7 days. Optional login (magic link, password, Google/GitHub) is identity, not a gate.

**Architecture:** **Next.js App Router** on Vercel Fluid Compute is the whole HTTP surface: pages **and** REST. Route Handlers (`app/v1/.../route.ts`, ceremony POSTs) use **`export const runtime = "nodejs"` — not Edge** (pdf-lib / `@signpdf` need Node). No Hono. Five REST routes + OpenAPI + llms.txt + MCP **stdio and HTTP** (`send` / `status` / `download`), `/s/[token]` page, decline, reminders, `envelope.completed` webhook, a public one-off drop. Pages use **shadcn/ui on Base UI**. Completing the last signer runs one module: append signature page → PKCS#12 ByteRange seal → SHA-256 of sealed bytes → sibling certificate PDF. If seal throws, the envelope stays pending. Free path: sender OTP then a hashed `sign_tmp_` key scoped to that envelope (dies at `shred_at`). Logged-in path: Supabase Auth (magic link, password, Google, GitHub); user mints `sign_live_` keys. Signers never get an account. Keys never sign.

**Tech Stack:** Node 22+, TypeScript ESM, **Next.js** (App Router + Route Handlers) + Zod, Drizzle + **Supabase Postgres** (PGlite in tests), `@supabase/supabase-js` for Auth **and Storage**, filesystem `BlobStore` in tests only, `pdf-lib` + `@signpdf/signpdf` + `@signpdf/placeholder-pdf-lib` + `@signpdf/signer-p12`, **Resend** (`resend` SDK), **Stripe** Checkout + webhook, Vercel Cron for shred, `nanoid`, `bcrypt`, Vitest, `@modelcontextprotocol/sdk`, **Tailwind v4 + shadcn/ui (`--base base-ui`)**. Apache-2.0. No Hono.

Sources: [product plan](../../2026-08-19-product-plan.md), [OSS competitor research](../../research/2026-08-20-competitor-research.md). Steal practices, never vendor AGPL code.

## Global Constraints

- Its own product. Not a suite SKU, not an industry fork. Do not import `ss-core` or other suite packages.
- Working title **Sign**. Do not rename to Secure Sign in this slice.
- License: **Apache-2.0**. No AGPL file may be copied in.
- Primitive, not suite: no field placer, templates, folders, tenants, seats, SSO, SMS, bulk, branding, saved packets.
- **Free path never requires login.** Homepage is PDF drop + curl. “Log in” is a small link.
- **HTTP:** Next.js Route Handlers + Zod. Tests call exported `GET`/`POST` with `new Request(...)`. Inject `{ db, store, mailer, now }` via `src/lib/deps.ts` (`setDeps` / `getDeps`) so PGlite tests do not boot Supabase. **No Hono.** No tRPC. No Server Actions as the public API.
- **UI:** Next.js App Router + Tailwind v4 + **shadcn/ui on Base UI** (`npx shadcn@latest init -d --base base-ui`). Not Radix. Not AI Elements. Not Vite. Seal routes `export const runtime = "nodejs"`. shadcn is Button/Input/Label/Card/Checkbox/Alert only — no sidebar kit, no template CMS.
- Human always signs. Bearer keys authenticate the *caller*; they never skip the signer and never auto-sign.
- Three lanes: (1) no-login OTP → `sign_tmp_`; (2) Supabase Auth session (magic link, password, Google, GitHub) + mint `sign_live_`; (3) signer `/s/:token` to **finish** — Auth is offered **after** complete, never before. No SAML/SSO. Never signup-to-sign.
- Funnel: done screen + completion email CTA “Keep it in a cabinet — create a free account.” Cabinet lists jobs the proven email **sent or signed**. Logged-in signer may download those PDFs; may not DELETE the sender’s envelope. Pro `extendKeep` covers both.
- First slice: PDF **multipart bytes only** (no URL fetch — SSRF). N signers, sequential, role always `signer`.
- Signer credential is `/s/:token` (unguessable nanoid, hashed at rest). GET/DELETE/PDF require a Bearer tmp or live key. Envelope UUID alone is not enough.
- Two clocks: `expires_at` = **7 days to sign**. Free `shred_at` = **7 days after completion** (if never signed, shred at `expires_at`). **Pro** (`accounts.plan = pro`) sets `shred_at` = completion + **1 year**. Not unlimited on cloud. Tmp key dies with `shred_at`. Hard delete, tombstone in audit, no restore.
- Packaging: **Free + Pro $19/mo**. Login is not a plan. Live keys after login on Free (quiet cap still applies). No seats, no team invites, no Enterprise SKU in this slice.
- PDF: append a signature page; do not overlay original pages. Hash **after** seal. Certificate is a **sibling** PDF, not appended after hashing.
- Completion email body must include: `Download this. We delete it on [date].`
- Cloud: Vercel (Next.js pages + Route Handlers, Cron) + Supabase (Postgres, Auth, Storage) + Resend (mail) + Stripe Checkout (**Pro $19/mo**, one Price). No Vercel Blob. No Hono. No function-filesystem writes. No Edge for seal/crypto. No PostgREST as the public API; RLS on, no `anon` grants. Storage bucket `envelopes` is private; server uses the service role.
- Quiet Free send cap: **20 envelopes / 30 days / verified sender email** (and per `user_id` when logged in on Free). Pro lifts it. Do not put the number on the homepage.
- Self-host: `supabase start` + `next start`. Stripe off. Mail via Resend or SMTP. Same REST + OpenAPI + stdio MCP, no license key, no Pro 404.
- Example PDF copy may be a repair authorization / direction to pay — do not market “good enough for a California statutory POA.”

**Interfaces:**

  - `newSigningToken(): { raw: string; hash: string }` — `nanoid(21)`, hash = `sha256Hex(raw)`

  - `newTmpKey(): { raw: string; prefix: string; hash: string }` — `sign_tmp_` + 32 hex bytes
  - `newLiveKey(): { raw: string; prefix: string; hash: string }` — `sign_live_` + 32 hex bytes
  - Prefix = first 12 chars of raw. Hash = `sha256Hex(raw)`.

describe("tokens", () => {
  it("hashes signing tokens; raw is not the hash", () => {
    const t = newSigningToken();
    expect(t.raw).toHaveLength(21);
    expect(t.hash).toBe(hashSigningToken(t.raw));
    expect(t.hash).not.toBe(t.raw);
