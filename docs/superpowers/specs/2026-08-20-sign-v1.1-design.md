## 1. Intent

v1.1 is the next slice of the same $19 Pro SKU. No new Stripe Price. No field placer. No custom domain. Certificate stays factual.

Three extras, built in this order in one plan:

1. **Branding** — display name + logo on invite/reminder/completion/decline mail and the signing page.
2. **Saved packets** — store a PDF + ordered signer *roles*; send that file again by filling names and emails.
3. **Team invites** — more people on **this** Pro cabinet. Soft cap 10 including the owner. Not billed per person.

Cloud **Free** (including logged-in Free) does not get these. They get `403` `{ error, code: "pro_required" }` and an upgrade CTA on the pages. **Self-host** (`SELF_HOST=1`) is always entitled.

---

## 2. Non-goals

- Custom sending domain, white-label DNS, or changing `FROM_EMAIL`
- Logo or display name on the sealed PDF appearance page or the sibling certificate
- Field placer, `{{sig}}` tags, template CMS, folders
- New MCP tools (still `send` / `status` / `download`)
- Seats, a second SKU, Stripe Customer Portal, SSO/SAML
- Signup-to-sign; ceremony still finishes on `/s/:token` alone
- URL ingest
- A user belonging to multiple cabinets

## 3. Entitlement

```ts
isEntitled(account): boolean
  // true if getEnv().SELF_HOST is "1" or "true"
  // else true if account?.plan === "pro"
```

**Cabinet** is the billing owner plus active members.

- A logged-in user who is not a member of someone else's cabinet **is** their own cabinet owner (even on Free).
- A user who accepted an invite uses the **owner's** cabinet for branding, packets, team list, Pro keep, and the send-cap lift.
- Writes that change branding or invite/remove members: **owner only**.
- Packet create/update/delete/send: owner **or** active member.
- Envelope `userId` stays the person who sent. Retention and cap use the **cabinet owner's** entitlement.

`SELF_HOST` is a new env string, default `""`. Unset in Vercel cloud. Set in self-host README / `.env.example` comment. Tests leave it unset and set `accounts.plan`.

## 4. Branding

### Data

On `accounts` (the **cabinet owner** row):

- `display_name` text, nullable, 1–80 chars once set, trimmed, no HTML
- `logo_path` text, nullable — BlobStore key `branding/{ownerUserId}/logo`

Logo bytes: PNG (`89 50 4E 47`) or JPEG (`FF D8 FF`), max **256 KiB**. No GIF/WebP/SVG. No resize.

### HTTP

Session cookie **or** `sign_live_` (never `sign_tmp_`, never `?apiKey=`).

| Method | Path | Who | Result |
|---|---|---|---|
| `GET` | `/v1/branding` | owner or member | `{ display_name, has_logo }` from the owner account. `403 pro_required` if cabinet not entitled |
| `PUT` | `/v1/branding` | owner | multipart or JSON. Fields: `display_name` (string or empty to clear), optional `logo` file. `403` if not owner or not entitled |
| `DELETE` | `/v1/branding/logo` | owner | clears `logo_path` and deletes the blob |
| `GET` | `/s/:token/logo` | signing token | `200` image bytes if that envelope's cabinet has a logo; `404` otherwise. Not a public unguessable account URL |

`GET /v1/branding` for a Free solo user: `403 pro_required`.

### Surfaces

- **Signing page:** if `display_name` or logo, show them above the title. Ceremony JSON grows `{ display_name: string | null, has_logo: boolean }`. Image `src=/s/{token}/logo`.
- **Mail:** invite, reminder, completion, decline, send-live. First line uses display name when set: `{displayName} ({senderEmail}) asked you to sign…`. Optional `html` on `MailMessage`; Resend sends `html` when present. Logo is a CID attachment `content_id=brand-logo` when the owner has a logo. **OTP mail is not branded.**
- **Certificate and sealed appearance page:** unchanged. Tests must extract certificate text and assert it does not contain the display name.

No custom From header.

### UI

`/settings/branding` — logged-in. If not entitled, copy + link to `/upgrade`. If member (not owner), read-only name/logo. If owner and entitled, form: display name, logo file, save, remove logo.

Cabinet header gains a **Branding** link.

## 5. Saved packets

A packet is **PDF bytes + ordered role names**. Roles are labels (`Customer`, `Shop`), not people. No fields.

### Data

`packets`

- `id` uuid PK
- `owner_user_id` uuid not null — cabinet owner
- `created_by_user_id` uuid not null
- `title` text not null
- `storage_path` text not null — BlobStore `packets/{id}/original.pdf`
- `created_at` timestamptz

`packet_roles`

- `id` uuid PK
- `packet_id` uuid → packets.id
- `signing_order` int not null
- `role_name` text not null

Enable RLS. No anon grants. Quiet cap **50 packets per cabinet**. Error `400` `{ code: "packet_limit" }`.

### HTTP

Session or live key. Entitled cabinet required.

| Method | Path | Body | Result |
|---|---|---|---|
| `GET` | `/v1/packets` | | `{ packets: [{ id, title, roles, created_at }] }` for this cabinet |
| `POST` | `/v1/packets` | multipart `title`, `roles` JSON `[{ "role_name" }]`, `file` PDF **or** `envelope_id` to copy the original PDF + default role names from signer names | `201` packet |
| `GET` | `/v1/packets/:id` | | packet + roles |
| `PATCH` | `/v1/packets/:id` | JSON `title` and/or `roles` | `200`. Does not replace the PDF |
| `DELETE` | `/v1/packets/:id` | | `204`. Deletes blob + rows |
| `POST` | `/v1/packets/:id/send` | JSON `{ "signers": [{ "name", "email" }] }` | Creates a normal envelope through the existing send path (same clocks, invite, cap). `signers.length` must equal role count, order = `signing_order`. `201` same shape as live `POST /v1/envelopes` |

Send-from-packet uses the caller's identity as sender (`userId` = caller, `sender_email` = caller email). Branding/keep/cap follow the cabinet owner.

PDF rules match create-envelope: magic `%PDF` or `application/pdf`, max 20 MiB.

### UI

`/packets` — list, create (upload + role names), send (fill name/email per role). Cabinet row on envelopes **you sent** (original PDF still present): **Save as packet** (POST with `envelope_id`). Free: upgrade CTA. Members can create/send.

No new MCP tool. Agents keep attaching PDF bytes to `send`.

## 6. Team invites

### Data

`cabinet_members`

- `id` uuid PK
- `owner_user_id` uuid not null
- `email` text not null (normalized lower)
- `user_id` uuid nullable — set on accept
- `status` `invited` \| `active`
- `token_hash` text unique not null
- `invited_at` timestamptz not null
- `accepted_at` timestamptz nullable

Unique `(owner_user_id, email)`. Owner is **not** a row in this table. Cap: `1 + count(rows for owner) <= 10`. `400` `{ code: "team_full" }`.

Invite token: nanoid 21, hashed at rest (same helper as signing tokens). Raw token only in the invite email. Expires **7 days** after `invited_at`.

### HTTP

| Method | Path | Who | Result |
|---|---|---|---|
| `GET` | `/v1/team` | owner or active member | `{ owner_email, members: [{ id, email, status, role: "owner"\|"member" }], entitled }` |
| `POST` | `/v1/team/invites` | owner, entitled | JSON `{ email }`. Mails accept link `/team/accept?token=`. `201` `{ id, email, status: "invited" }`. Re-invite same email while `invited` remints the token and resets `invited_at`. Active email: `409` `{ code: "already_member" }` |
| `DELETE` | `/v1/team/members/:id` | owner | Removes invited or active member. Cannot delete the owner. `204` |
| `POST` | `/team/accept` | logged-in session | JSON `{ token }` or form. Session email must match invite email. Sets `user_id`, `status=active`, `accepted_at`. |

Accept rejects (`409`) when:

- already an active member of **any** cabinet (`code: "already_on_a_team"`)
- the user already **owns** at least one `cabinet_members` row (`code: "already_owns_a_team"`)
- on cloud (not `SELF_HOST`), `accounts.plan === "pro"` (`code: "already_pro"`) — they have their own paid cabinet; they should invite the other way

Expired or unknown token: `410` / `404`.

### Visibility and authority

After Task 8, `listEnvelopes` for a cabinet member or owner includes envelopes whose `userId` is the owner **or** any **active** member, plus envelopes the caller **signed** (existing email match).

`can_delete` is true if the caller sent it (`envelope.userId === caller`) **or** the caller is the cabinet owner.

Create-envelope live/session path: if the caller is a member, `userId` is still the caller; send-cap and later keep use `isEntitled(ownerAccount)`.

`extendKeep` / last-signer `keepDays`: treat the sender's **cabinet owner** as the Pro account, not only `envelope.userId`'s own row. Signer-is-Pro still lifts keep (existing v1 behavior).

### UI

`/team` — list owner + members, invite form (owner), remove (owner). `/team/accept` — if not logged in, redirect to `/login?email=&next=/team/accept?token=`. If logged in as the wrong email, say so. If ok, POST accept.

Cabinet header: **Team** link.

## 7. Auth and errors

Same as v1:

- Errors `{ "error": string, "code": string }`
- No `?apiKey=`
- Live key or session for cabinet APIs; tmp key is envelope-scoped and **cannot** read branding/packets/team
- Route Handlers `runtime = "nodejs"`
- Tests: PGlite + `setDeps` + fake AuthAdapter (same pattern as `src/test/keys.test.ts`)

Codes used: `unauthorized`, `pro_required`, `forbidden` (member tried owner-only write), `invalid_logo`, `invalid_pdf`, `packet_limit`, `team_full`, `already_member`, `already_on_a_team`, `already_owns_a_team`, `already_pro`, `invalid_request`, `not_found`.

## 8. Architecture

Stay on the v1 composition root.

```
src/lib/entitlement.ts   isEntitled, TEAM_CAP=10, PACKET_CAP=50, LOGO_MAX_BYTES
src/lib/caller.ts        requireCaller(req) → session | live key user
src/lib/cabinet.ts       cabinetForUser(db, userId)
src/lib/branding.ts      brandingKey, parseLogo
src/routes/branding.ts
src/routes/packets.ts
src/routes/team.ts
```

`cabinetForUser`:

1. Look up `cabinet_members` where `user_id = userId` and `status = active`. If found, owner is that row's `owner_user_id`.
2. Else owner is `userId`.
3. Load owner `accounts` row (email, plan, display_name, logo_path).
4. Load all `cabinet_members` for that owner.
5. Return `{ ownerUserId, ownerEmail, entitled, displayName, logoPath, members, memberUserIds }` where `memberUserIds` is `[ownerUserId, ...active user_ids]`.

BlobStore already abstracts fs vs Supabase. Branding and packet PDFs use the same store. Packet/logo keys are not under `envelopes/{id}/` so shred of an envelope cannot delete a packet.
